# 에이전트 설정

[English](agent-setup.md) | [한국어](agent-setup.ko.md)

## 프로젝트 전용 Codex 스킬

패키지 import와 컴파일 후 Editor 초기화가 `Skills~/unity-agent-coordination`을 해당 Unity 프로젝트의 `.agents/skills/unity-agent-coordination`에 복사합니다. 전역 스킬이나 `AGENTS.md` 자동 수정은 필요하지 않습니다. 미수정 관리 파일만 갱신하고 사용자 수정과 비관리 스킬은 경고와 함께 보존합니다. 정상적인 Package Manager 제거에서는 미수정 패키지 관리 파일을 정리합니다. Unity가 닫힌 상태에서 제거하면 프로젝트 스킬이 남을 수 있지만 패키지가 없으면 그 스킬도 사용을 중단합니다.

기존 전역본은 프로젝트 스킬이 생성된 것을 확인한 뒤 정리합니다. 생성 파일의 커밋/ignore 여부는 프로젝트의 일반 운영 방식으로 정하며 번호표 소유권과는 무관합니다.

패키지를 갱신한 뒤 생성된 프로젝트 스킬에 활성 턴 종료 전 정리 규칙이 포함되어 있는지 확인합니다. 사용자 수정 때문에 자동 갱신되지 않았다면 그 수정을 보존하면서 이 규칙을 해당 사본에 병합합니다.

## 기존 Unity bridge 사용

대상 Editor 안에서 `UnityAgentCoordinationCommandRouter.ExecuteJson(string)`을 호출할 수 있는 bridge를 사용합니다. 선택형 Coplay 10.1.2–10.x 어댑터는 `manage_unity_agent_coordination`을 노출합니다. 대기열이 MCP provider를 설치하거나 관리하지 않습니다.

다른 에이전트는 프로젝트 지침에서 [프로토콜](mcp-protocol.ko.md)을 연결하면 됩니다. 고유 세션 ID로 번호표를 발급하고 자기 차례를 기다린 뒤 현재 활성 대화 턴 안에서만 점유·사용합니다. finally/정리 단계에서 자신이 시작한 작업을 완료하거나 안전하게 중단한 뒤 사용 중인 번호표는 반납하고 대기 중인 번호표는 취소합니다. 턴을 끝내거나 사용자의 응답·확인·승인을 기다리려고 작업을 멈추기 전에 제거 여부까지 확인합니다. 실패하거나 같은 대화에서 작업을 계속할 예정이어도 같으며, 세션 ID는 유지할 수 있지만 재개 시 새 번호표를 발급받습니다. 정리 결과가 불명확하면 `status`로 확인하고 미해결 상태를 반납 완료로 보고하지 않습니다. 모든 참여자가 이 약속을 지켜야 합니다. 다른 bridge 명령을 가로채지는 않으며 패키지는 턴 종료나 사용자 입력 대기를 감지할 수 없습니다.

발급 시 `program`, `model`, `reasoning_effort`, `session_name`도 입력할 수 있습니다. 에이전트는 확인된 값 또는 `Unknown`을 기입하며 기존 클라이언트는 생략할 수 있습니다. 이전 세션 종료 후 패키지·bridge·스킬을 함께 갱신합니다. 이전 작업 등록과 검증 API는 제거됐습니다.
