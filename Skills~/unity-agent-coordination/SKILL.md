# Unity Agent Coordination

Coordinate Editor use with one ticket queue in the current Unity project. This skill is installed in `.agents/skills/unity-agent-coordination` by the package. Use the existing `com.olivecrow.unity-agent-coordination` package and its bridge; if absent, stop rather than installing or restoring it. Do not install a global skill or choose/manage an MCP provider.

## When to draw a ticket

Draw a ticket before the first operation that uses or can affect the live Editor: inspection, import/refresh, compilation, tests, Play Mode, builds, scene/prefab edits, or scripts/assets written in the project currently open in Unity. Read-only file inspection, documentation, planning, and file edits outside the live project need no ticket. Do not launch another Editor as a queue workaround.

## Ticket lifetime: one active conversation turn

Hold a ticket only within the current active conversation turn. Return it as soon as the current Editor work finishes, and always clean up before ending the turn with a final response or suspending work to wait for the user's reply, confirmation, or approval. This applies even when the overall task is unfinished and will continue in the same conversation. Progress messages and tool waits while continuing the current work do not end the turn.

The `session_id` may persist across turns; a ticket must not. On a later turn or Editor batch, enqueue a new ticket and wait in FIFO order again. If your own ticket was left over from an earlier turn, clean it up and verify removal before enqueueing again; do not reuse its ownership or queue position.

## Required metadata before enqueue

**Look up the current session's metadata before every `enqueue`.** Check the runtime and session context, and use the host's available metadata lookup tools for any values you have yet to verify. Send all four fields: `program` for the host program, `model` for the actual running model, `reasoning_effort` for the selected reasoning level, and `session_name` for the actual conversation title.

Use verified values as reported by the host. Never guess, use a task label or session ID as the title, or send blanks. Use the literal `Unknown` for a field only after checking the available sources and being unable to verify that value. If a lookup is available, use it even when the value is absent from the prompt. Do not enqueue until the lookup is complete and all four fields are populated.

## Ticket lifecycle

1. Select the existing bridge instance for the intended Unity project. Create a unique `session_id` for this task and retain it throughout the ticket lifecycle.
2. Complete the required metadata lookup, set up the optional listener as described in step 3, and call `enqueue` with `session_id`, a short `label`, and all four metadata fields. Save `ticket.ticket_id` and verify that the returned ticket contains all four submitted values before calling `acquire`. If the metadata differs, reconcile with `status` and clean up your incorrect ticket if it is still outstanding. Draw a replacement only after correcting the request or bridge, because an enqueue retry preserves the original ticket's metadata. If the replacement still differs, clean up, report the problem, and stop before using the Editor.
3. Prefer the optional local notification channel if PowerShell 7 (`pwsh`) and a persistent shell tool session are available. Before enqueue, start `pwsh -NoProfile -File .agents/skills/unity-agent-coordination/scripts/wait_for_turn.ps1 -ProjectPath <Unity-project-path> -Timeout 120` as a persistent session. Use `pwsh` even on Windows; if it is unavailable or script execution is blocked, use the status fallback instead of changing execution policy. Read its first `ready` JSON line and supply `notification_token` on enqueue. If enqueue already shows your ticket as next, stop the watcher and acquire immediately. Otherwise, keep the watcher session alive and wait for its `turn` output; then call `status`, verify the ticket ID, and acquire only when it is next. A timeout, watcher exit, connection loss, or domain reload requires `status` reconciliation; retry with backoff if notification is unavailable. An enqueue retry preserves the original token, so cancel your waiting ticket before registering a replacement watcher. Notifications are best-effort hints, not ownership or guaranteed delivery. A finished agent turn cannot be woken by this channel.
4. Poll `status` with backoff if the notification channel is unavailable, doing useful independent work while waiting. Do not use or trigger the Editor until `queue.next_ticket_id` equals your ticket and `acquire` succeeds with your session and ticket IDs. `not_your_turn` and `editor_busy` preserve your place while you continue working in this turn. If you end the turn or suspend work for user input, cancel your waiting ticket. Never cancel another session's ticket or reset its queue.
5. While using the Editor, check that `queue.active_ticket_id` is still your ticket immediately before each batch of Editor operations or import-triggering writes. After acquiring the ticket and before starting the requested work, run Unity's normal Ctrl+S save command. Check open editor windows with their own save commands, such as Shader Graph, and save any pending changes there as well. Verify that the saves succeeded before starting the work. Use the existing bridge for the actual work. The package does not run those operations for you.
6. In a finally/cleanup step, finish or safely stop Editor operations you started. While you still own the active ticket, repeat the Ctrl+S save and window-specific save checks from step 5 before calling `release`. If a save fails, report the affected item and error to the user and still clean up the ticket. If you are still waiting, `cancel` your ticket. Do this on success, failure, abandonment, and before ending the turn or suspending work for user input. Do not acquire a waiting ticket just to return it.
7. Check cleanup success and confirm your ticket is absent from the returned `queue.tickets`. If the response is missing, failed, or ambiguous, call `status` to reconcile before retrying cleanup of your own ticket. If cleanup remains impossible or unconfirmed, stop Editor use and report the `session_id`, `ticket_id`, and cleanup error to the user; do not claim the ticket was returned or the queue is free.

The package cannot detect conversation turn endings or user-input waits; the agent must perform this cleanup explicitly. Tickets survive compilation/domain reload and do not expire automatically. If the owner disappears, report the blocked queue. The user can cancel the individual ticket in the Editor window after confirming that the session has stopped using the Editor. Do not use timeouts as permission to bypass ownership or edit queue files.

The protocol has only `status`, `enqueue`, `acquire`, `release`, and `cancel`. Call the installed adapter (`manage_unity_agent_coordination` for Coplay) or a bridge to `UnityAgentCoordinationCommandRouter.ExecuteJson(string)`. If a stale schema rejects any metadata field or `notification_token`, use the project-scoped custom-tool dispatcher (for Coplay, `execute_custom_tool` with `tool_name: manage_unity_agent_coordination` and a `parameters` object), or reconnect to refresh tool discovery. Do not omit metadata fields to work around a stale schema or silently drop a notification token. Queue state is internal to `Library/UnityAgentCoordination`; never read or write it directly.

Read [references/mcp-protocol.md](references/mcp-protocol.md) when constructing an unfamiliar command or adapting a bridge.
